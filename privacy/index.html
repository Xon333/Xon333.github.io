Privacy policy

Last reviewed: 14 November 2026.

Otis Heric operates t3code for personal use. This policy covers the Google integrations associated with Library-boopmark and YouTube Read Access, and their relationship to the private Library tools. Contact heric.otis@gmail.com with privacy questions or deletion requests.

Google data and purpose

  • The separate YouTube read workflow has the youtube.readonly permission. Local results include channel information, subscriptions and playlist metadata for personal review. This permission does not authorize subscription or playlist changes.
  • The Data Portability workflow has the dataportability.myactivity.youtube permission and an owner-requested export of myactivity.youtube, covering YouTube activity. A local job record requests 180-day access. That request does not establish the actual lifetime of Google's authorization.
  • The installed Library uses local-password sign-in. Its direct YouTube connector is not installed. No completed import of the Google activity export into Library was established in the latest review.

Storage and access

The separate Google credentials and YouTube results are stored in the operator's local user account on his Mac. The reviewed credential files have owner-only file permissions. Library stores saved resources, metadata and generated classifications on the operator's private OMV server, with PostgreSQL and local file storage. Model API keys in Library settings are encrypted by the application. These facts do not imply that all stored data or backups are encrypted.

Model processing and other recipients

Library uses OpenAI for classification. Classification requests can contain a saved resource's URL, title, description, captured text, a bounded personal-note hint, the subject catalogue and selected examples from saved resources. The implementation also supports other configured model providers, including Anthropic; provider selection controls the recipient.

The OpenAI classification implementation requests store: false. This is not a guarantee of zero provider retention. Model providers apply their own data-handling terms.

The review did not establish that the separate Google export or subscription results have been sent to OpenAI or another model provider. Saving Google-derived content into Library and classifying it could send that content or metadata through the classification flow described above.

Google receives authorization and API requests. A public website's hosting provider receives ordinary page requests, including network information such as an IP address. These static pages contain no analytics scripts, remote fonts, forms or Google sign-in flow.

Retention, deletion and revocation

A fixed retention period and an automated deletion schedule for the separate YouTube results, Google exports and backup copies have not been established. Do not interpret the requested 180-day authorization as a data-deletion deadline.

The operator can delete saved bookmarks in Library. Deleting a bookmark does not establish that every copied file, export, backup or model-provider record has been erased. Contact the operator to request deletion of locally retained credentials, exports and associated copies; a guaranteed completion time has not been established.

You can review and revoke Google access at Google Account connections. Revocation stops future authorized access; it does not itself delete already stored copies.

Changes

This page must be reviewed when the integrations or data handling change. It describes the behavior established at the review date and identifies the remaining unknowns.
